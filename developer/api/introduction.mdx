The Yuko API is organized around REST. Our API has predictable, resource-oriented URLs and uses standard HTTP response codes to indicate success or failure. All request and response bodies are JSON.

## Base URL

```text
https://api.yukoapp.com/api/v1/public
```

## Request format

All requests must include the following headers:

| Header | Value |
| :----- | :---- |
| `Authorization` | `Bearer YOUR_API_KEY` |
| `Accept` | `application/json` |
| `Content-Type` | `application/json` (for `POST` requests with a body) |

<Tip>Always send `Accept: application/json`. Without it, a few framework-level errors (such as rate limiting or an unknown URL) may come back as HTML instead of JSON.</Tip>

## Response format

All responses return JSON. Successful responses wrap the result in a `data` key; list endpoints also return `meta.pagination`. Error responses return an `error` object with a machine-readable `code` and a human-readable `message`:

```json
{
  "error": {
    "code": "insufficient_scope",
    "message": "Your API token does not have the required 'rewards' scope for this action"
  }
}
```

## Authentication and scopes

Authenticate with a REST API key as a Bearer token. Each key is limited to the scopes the merchant chose, written as `read:<scope>` or `write:<scope>`. See [Authentication](/developer/api/authentication) and [Scopes](/developer/api/scopes).

## Identifying customers

Look up a single customer by [Shopify ID](/developer/api/retrieve-a-customer-by-shopify-id), [Yuko ID](/developer/api/retrieve-a-customer-by-id), [email](/developer/api/retrieve-a-customer-by-email) or [phone](/developer/api/retrieve-a-customer-by-phone). Endpoints that act on a customer, such as [Credit points](/developer/api/credit-points), take an `identifier` that can be any of these. See [Identifying customers](/create-or-update-a-customer-identity#identifying-customers).
