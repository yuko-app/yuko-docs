---
title: "Rate Limits"
description: "How many requests you can make to the Yuko API, and how to handle 429 responses."
---

To keep the platform stable for everyone, all API endpoints are rate limited.

## Limit

You can make up to **100 requests per minute** to each endpoint. The limit is counted separately for each IP address and each request path. Once you reach it, further requests to that path return `HTTP 429 Too Many Requests` until the minute is up.

<Note>The customer lookup endpoints include the customer in the path (for example `/customers/by-email/{email}`), so each customer's URL has its own limit. Endpoints that take the customer as a parameter, such as [List customer activities](/developer/api/list-customer-activities), share one limit across all customers.</Note>

## Rate limit headers

Every response includes `X-RateLimit-Limit` and `X-RateLimit-Remaining` headers. A `429` response also includes a `Retry-After` header with the number of seconds to wait, and its body is:

```json 429
{
  "message": "Too Many Attempts."
}
```

## Staying within the limit

- Wait for the `Retry-After` period before retrying a `429`, and use exponential backoff for repeated failures.
- Cache configuration data such as rewards, VIP tiers and ways to earn. It rarely changes.
- Send `Accept: application/json` so that a `429` comes back as JSON.
