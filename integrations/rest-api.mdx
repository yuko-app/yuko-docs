## What you can do

The Yuko REST API exposes the same data the dashboard shows:

- List customers, and look one up by Shopify ID, Yuko ID, email or phone, with their points balance, referral link and VIP tier.
- List the rewards issued to a customer and their loyalty activity.
- Credit points, deduct a reward's points cost, and award points for a **Custom Action** earn rule.
- List rewards, ways to earn, booster campaigns, VIP tiers and membership plans, and get the referral program.

Full endpoint reference is in the **API Reference** tab — this page covers setup and best practices.

## When to use

- Custom storefronts (Hydrogen, headless).
- Awarding points for actions that happen outside your store, such as completing a survey, through a [Custom Action](/developer/api/credit-points-for-custom-action).
- Server-side automations that need to read Yuko data or adjust points.
- Moving points balances over from another loyalty program (customers must already exist in Yuko; they're synced from your store automatically).
- Building admin tools that show Yuko data alongside your other systems.

## Setup

<Steps>
  <Step title="Get REST API access">
    Go to **Apps → Yuko Loyalty → Integrations → REST API**. If you see **Approval required**, click **Contact support** and ask the Yuko team to turn on REST API access for your store. Once it's approved, this page takes you straight to the setup.
  </Step>
  <Step title="Create a key">
    Click **Create new key**. A store can have only one active key, so revoke the existing key first if there is one.
  </Step>
  <Step title="Name the key">
    Enter a **Private API Key Name** (for example, *Marketing Integration*) so you can tell your keys apart.
  </Step>
  <Step title="Choose the access level">
    Under **Select Access Level**, pick one:
    - **Full Access Key**: read and write access for every API scope.
    - **Read-Only Key**: read-only access for every API scope. It can't credit or debit points.
    - **Custom Key**: click **Next**, then on the **Customize API Scopes** screen set each scope to **No Access**, **Read Access** or **Read/Write Access**.
  </Step>
  <Step title="Create and copy the key">
    Click **Create** (or **Create API Key** for a custom key). The **Your Private Key** popup shows the key, which starts with `py_`. Copy it to a password manager or secrets store.
  </Step>
  <Step title="Authenticate requests">
    Send the key as a Bearer token in the `Authorization` header. Details: [Authentication](/developer/api/authentication).
  </Step>
</Steps>

## Managing keys

The **API keys** list shows each key's name, masked token (use **Show token** or **Copy token** to see or copy the full key), status, scopes, when it was last used, and when it expires or was revoked. You can search by token name.

To revoke a key, use the **Actions** column and confirm in the **Revoke API key** dialog. Any integration using the key loses access immediately, and this can't be undone.

## Authentication and scopes

All requests use Bearer token authentication. Each key only works for the scopes it was given; a request outside them returns `403 insufficient_scope`. The **Points**, **Referrals** and **Tiers** scopes also decide whether customer responses include the points balance, referral link and VIP tier. See **[Authentication](/developer/api/authentication)** and **[Scopes](/developer/api/scopes)**.

## Best practices

<Tip>**Give each key only the scopes it needs.** Use a **Custom Key** instead of full access where you can.</Tip>
<Tip>**Rotate your API key regularly** and immediately when a developer leaves. Because a store can have only one active key, revoke the old key, create a new one, and update your integration straight away. Requests fail in between.</Tip>
<Tip>**Cache configuration data** such as rewards, VIP tiers and earning rules instead of fetching it on every request. It rarely changes, and caching keeps you well under the rate limit.</Tip>
<Tip>**Name your key** after the system that uses it, so it's clear what breaks if you revoke it.</Tip>

## FAQs

<AccordionGroup>
  <Accordion title="Can I create more than one API key?">
    No. A store can have one active key at a time. To replace it, revoke the existing key, then create a new one.
  </Accordion>
  <Accordion title="Why does REST API say Approval required?">
    REST API access is turned on per store by the Yuko team. Click **Contact support** on that page and we'll enable it for you.
  </Accordion>
  <Accordion title="I lost my key. Can I see it again?">
    Yes. In **Integrations → REST API**, use **Show token** or **Copy token** on the key in the **API keys** list. If you think a key has leaked, revoke it and create a new one.
  </Accordion>
  <Accordion title="What's the rate limit?">
    See [Rate Limits](/developer/api/rate-limits) in the API Reference.
  </Accordion>
  <Accordion title="Can I revoke a key?">
    Yes. In **Integrations → REST API**, use the **Actions** column on the key and confirm **Revoke**. Revocation is immediate and can't be undone.
  </Accordion>
</AccordionGroup>
