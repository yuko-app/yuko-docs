## What you can do

The Yuko REST API exposes the same data the dashboard shows:

- List and retrieve customers and their points balances, tiers, memberships and rewards.
- Redeem rewards and add or deduct points.
- List rewards, VIP tiers, earning rules, booster campaigns and the referral program.
- Read activity feeds, points transactions and referrals.
- Estimate the points a cart will earn at checkout.

Full endpoint reference is in the **API Reference** tab — this page covers setup and best practices.

## When to use

- Custom storefronts (Hydrogen, headless).
- Server-side automations that need to read or write Yuko data.
- Moving points balances over from another loyalty program (customers must already exist in Yuko; they're synced from your store automatically).
- Building admin tools that show Yuko data alongside your other systems.

## Setup

<Steps>
  <Step title="Open REST API settings">
    Go to **Apps → Yuko Loyalty → Integrations → REST API** and click **Create new key**.
  </Step>
  <Step title="Name the key">
    Enter a **Private API Key Name** (for example, *Marketing Integration*) so you can tell your keys apart.
  </Step>
  <Step title="Choose the access level">
    Under **Select Access Level**, pick one:
    - **Full Access Key**: read and write access for every API scope.
    - **Read-Only Key**: read-only access for every API scope.
    - **Custom Key**: click **Next**, then on the **Customize API Scopes** screen set each scope to **No Access**, **Read Access** or **Read/Write Access**.
  </Step>
  <Step title="Create and copy the key">
    Click **Create** (or **Create API Key** for a custom key). The **Your Private Key** popup shows the key, which starts with `py_`. Copy it to a password manager or secrets store.
  </Step>
  <Step title="Authenticate requests">
    Send the key as a Bearer token in the `Authorization` header. Details: [Authentication](/developer/api/authentication).
  </Step>
</Steps>

## Managing keys

The **API keys** list shows each key's name, masked token (use **Show token** or **Copy token** to see or copy the full key), status, scopes, when it was last used, and when it expires or was revoked. You can search by token name.

To revoke a key, use the **Actions** column and confirm in the **Revoke API key** dialog. Any integration using the key loses access immediately, and this can't be undone.

## Authentication and scopes

All requests use Bearer token authentication. Each key only works for the scopes it was given; a request outside them returns `403 insufficient_scope`. See **[Authentication](/developer/api/authentication)** and **[Scopes](/developer/api/scopes)**.

## Best practices

<Tip>**Give each key only the scopes it needs.** Use a **Custom Key** instead of full access where you can.</Tip>
<Tip>**Rotate API keys regularly** and immediately when a developer leaves: create a new key, switch your integration to it, then revoke the old one.</Tip>
<Tip>**Cache configuration data** such as rewards, VIP tiers and earning rules instead of fetching it on every request. It rarely changes, and caching keeps you well under the rate limit.</Tip>
<Tip>**Tag every key with a name** so you can revoke a single integration without breaking others.</Tip>

## FAQs

<AccordionGroup>
  <Accordion title="Do I need a separate API key per integration?">
    Strongly recommended. It limits blast radius if one is leaked.
  </Accordion>
  <Accordion title="I lost my key. Can I see it again?">
    Yes. In **Integrations → REST API**, use **Show token** or **Copy token** on the key in the **API keys** list. If you think a key has leaked, create a new key and revoke the old one.
  </Accordion>
  <Accordion title="What's the rate limit?">
    See [Rate Limits](/developer/api/rate-limits) in the API Reference.
  </Accordion>
  <Accordion title="Can I revoke a key?">
    Yes. In **Integrations → REST API**, use the **Actions** column on the key and confirm **Revoke**. Revocation is immediate and can't be undone.
  </Accordion>
</AccordionGroup>
