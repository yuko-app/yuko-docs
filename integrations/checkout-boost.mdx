## Introduction

The **Checkout Boost** integration is a one-toggle setup that creates a **read-only REST API key** and a **signed key** so the Checkout Boost app can render Yuko loyalty (points balance, rewards) inside the Shopify checkout flow.

On the Integrations page, Checkout Boost is listed in the **Shopify Flow** category of the sidebar, but it isn't a Shopify Flow feature.

This is different from the general [REST API](/integrations/rest-api) integration — that one is for arbitrary API access. This one is a single-purpose, read-only credential pair named **Checkout Boost**.

## What it does

- Enabling it generates a **REST API key** (a `py_` key with read access to every API scope that supports reading) and a **signed key** (a `pysk_` key used to verify request authenticity).
- Both keys appear in the **Your Private Keys** popup, with copy and **Download Keys** options.
- While the integration is enabled, both keys stay available, masked, in the **API credentials** section of the page, where you can reveal and copy them.
- The Checkout Boost extension uses these keys to fetch the current customer's Yuko loyalty state during checkout (points balance, tier, available rewards) and render widgets accordingly.
- Disabling revokes both keys immediately.

<Tip>Click **Download Keys** in the popup to keep a copy. If you need the keys later, open the Checkout Boost page while the integration is enabled and copy them from **API credentials**.</Tip>

## When to use it

- You want to surface Yuko loyalty inside Shopify's **checkout** UI, not just the storefront.
- You're installing the Checkout Boost extension (or an equivalent that follows the same contract).
- You want a read-only key, with no write access to customer data.

## Before you start

<Check>You have the Checkout Boost extension installed (or ready to install) on your Shopify store.</Check>
<Check>You know where in your Checkout Boost extension setup to paste the REST API key and signed key.</Check>

## Enable Checkout Boost

<Steps>
  <Step title="Open Checkout Boost in Yuko">
    In Shopify admin, go to **Apps → Yuko Loyalty → Integrations**, and click **Checkout Boost**.
  </Step>
  <Step title="Toggle Enable">
    Switch on the **Checkout Boost** toggle. Yuko generates the two keys.
  </Step>
  <Step title="Copy or download the keys">
    The **Your Private Keys** popup shows the **REST API Key** and **Signed Key**. Copy them or click **Download Keys** and store them somewhere secure.
  </Step>
  <Step title="Paste the keys in the Checkout Boost extension">
    Open the Checkout Boost extension's setup page in Shopify admin and paste both keys into their respective fields.
  </Step>
  <Step title="Verify in checkout">
    Open your storefront's checkout as a signed-in customer. The Checkout Boost widget should now display the customer's Yuko points balance and available rewards.
  </Step>
</Steps>

## Disable Checkout Boost

Switch the toggle off and confirm in the **Disable Checkout Boost** dialog. Both keys are revoked immediately, and Checkout Boost can no longer read customer loyalty data.

<Warning>Disabling **doesn't** uninstall or reconfigure the Checkout Boost extension itself. You'll need to remove or update the keys in the extension separately.</Warning>

## Rotating the keys

To rotate:
1. Disable Checkout Boost (revokes the old keys).
2. Re-enable (generates a fresh pair).
3. Copy the new keys into the extension.

There's no separate rotate button today — the disable / re-enable flow is the rotation.

## Limitations

- **Read-only.** The generated REST API key can read Yuko data but can't write, so it can't redeem rewards or change points.
- **One key pair per store.** Regenerating invalidates the previous pair.
- **Extension setup is separate.** Yuko provisions credentials — you still need to install and configure Checkout Boost separately.

## FAQs

<AccordionGroup>
  <Accordion title="How is this different from the REST API integration?">
    The REST API integration lets you create arbitrary API keys with various scopes for any purpose (custom apps, headless commerce, etc.). Checkout Boost creates a **single read-only** key pair for the Checkout Boost app — one toggle, no configuration.
  </Accordion>
  <Accordion title="What if I lost the keys?">
    While the integration is enabled, open the Checkout Boost page and copy them from **API credentials**. If you'd rather issue new keys, disable and re-enable the integration, then update Checkout Boost with the new values.
  </Accordion>
  <Accordion title="Does the customer's Yuko data appear in checkout automatically after enabling?">
    Only after you also paste the keys into the Checkout Boost extension. Enabling Yuko's toggle generates the credentials; the extension is what actually renders the widgets during checkout.
  </Accordion>
  <Accordion title="Can I use this for a custom checkout extension I built?">
    If your custom extension follows the same key + signed-key contract as Checkout Boost, yes. Otherwise, use the general [REST API](/integrations/rest-api) integration and roll your own credentials.
  </Accordion>
</AccordionGroup>
