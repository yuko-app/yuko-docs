## Introduction

WappCloud is a WhatsApp Business API platform for sending template messages. Once connected, the [WhatsApp Workflow node](/workflows/whatsapp-node) can send your approved WappCloud templates whenever a loyalty event fires: points earned, reward redeemed, tier upgraded, points about to expire and so on.

For the provider-agnostic overview of how Yuko's WhatsApp integration works, see [WhatsApp](/integrations/whatsapp).

## When to use WappCloud

- You already send WhatsApp messages through WappCloud.
- You want loyalty events to trigger the same approved templates you use elsewhere.
- You want URL buttons in your messages that link each customer to a personalised page.

## Before you start

<Check>You have an active WappCloud account connected to the WhatsApp Business API.</Check>
<Check>You have at least one **approved** template in WappCloud.</Check>
<Check>You can find two credentials in WappCloud: an **API key** and an **access token**.</Check>

## Connect WappCloud to Yuko

<Steps>
  <Step title="Get your WappCloud credentials">
    In WappCloud, generate an API key under **More → API → External API**. Then copy your access token under **More → API Access**.
  </Step>
  <Step title="Open WappCloud in Yuko">
    In Shopify admin, go to **Apps → Yuko Loyalty → Integrations**, pick the **WhatsApp** category from the left sidebar, and click **WappCloud**.
  </Step>
  <Step title="Enter both credentials and connect">
    Paste the key into **API Key** and the token into **Access Token**, then click **Connect Integration**. Both fields are required. The page shows **Connected**.
  </Step>
  <Step title="Add a WappCloud step to a workflow">
    Open any workflow, click **+**, pick **WhatsApp**, and choose the **WappCloud** card from the provider list.
  </Step>
</Steps>

<Note>Yuko doesn't test the credentials when you connect. If the key or token is wrong, the integration still shows **Connected**, but WhatsApp steps fail at send time with WappCloud's error. Check a test send after you connect.</Note>

## Configure the WappCloud step in a workflow

| Field | What it is | Example |
|---|---|---|
| **Template Name** | Approved template name from WappCloud, exactly as in Meta Business Manager (no spaces) | `loyalty_points_earned` |
| **Add CTA Button** *(optional)* | Turn on to add URL call-to-action buttons with dynamic suffixes | On |
| **CTA Button Count** | How many URL buttons the template has (1–2). Shown when **Add CTA Button** is on. | `1` |
| **CTA Button URL Suffixes** | One dynamic suffix per button, appended to the button's base URL in the template. Supports [shortcodes](/workflows/whatsapp-node#shortcodes). | `{{reward_code}}` |
| **Parameter Count** | Number of body variables in the template (1–10) | `2` |
| **Template Parameters** | One value per body variable, in order. Supports [shortcodes](/workflows/whatsapp-node#shortcodes). | `{{first_name}}`, `{{points_balance}}` |

You must fill in exactly as many parameters and button suffixes as the counts you set. Template names can't contain spaces.

<Tip>The **Template Name**, parameter count and number of URL buttons must match the approved template in WappCloud exactly. A mismatch is the most common reason a send fails.</Tip>

WappCloud doesn't take a language code from Yuko. The template's language is the one it was approved with in WappCloud.

Yuko sends the customer's phone number from Shopify and adds a leading `+` if it's missing, so make sure stored numbers include the country code.

## Example use case

**Reward-redeemed message with a shop link**

1. In WappCloud, get a template called `loyalty_reward_redeemed` approved, with two body variables (first name, reward name) and one URL button whose base URL is your store's discount link.
2. In Yuko Workflows, build: **Trigger: Redeem Points** → **WhatsApp (WappCloud)**.
3. Set Template Name = `loyalty_reward_redeemed`, Parameter Count = `2`, Parameters = `{{first_name}}`, `{{reward_name}}`.
4. Turn on **Add CTA Button**, set CTA Button Count = `1`, and Button 1 URL Suffix = `{{reward_code}}`.
5. Turn on the workflow.

## Limitations

- **Approved templates only.** Meta must approve every template before it can be sent.
- **No template authoring inside Yuko.** Create and edit templates in WappCloud.
- **Up to 10 body parameters and 2 URL buttons per step.**
- **No delivery status in Yuko.** The workflow step is marked completed or failed based on WappCloud's API response, not on delivered or read events.

## FAQs

<AccordionGroup>
  <Accordion title="The step is marked failed. What do I check?">
    1. The API key and access token are correct. 2. The template name matches WappCloud exactly. 3. The template is approved. 4. The parameter count and button count match the template. 5. The customer has a phone number in Shopify. The failure reason is shown in the workflow's [Analytics](/workflows/analytics).
  </Accordion>
  <Accordion title="Can I use the same template in several workflows?">
    Yes. Each WhatsApp node points to one template, and any number of nodes can use the same one.
  </Accordion>
  <Accordion title="How do I rotate the API key or access token?">
    Disconnect WappCloud in Yuko, generate new credentials in WappCloud, then connect again with both values.
  </Accordion>
</AccordionGroup>
